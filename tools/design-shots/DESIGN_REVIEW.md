# PufferWork · 页面与视觉设计评审材料包

## 项目一句话
双人共享生活工作台（静态单页应用），包含仪表板、待办、健身日记、留言板、相册、吃饭转盘、心愿墙。视觉风格：成熟温暖·像素河豚主题，珊瑚橙主色 + 暖米背景 + 衬线标题。

## 设计意图（请先看这些再看图）
- **品牌**：Puffer（河豚），所有视觉元素都围绕"温暖、生活感、双人陪伴"展开
- **成熟感**：避免过于卡通或少女心，用衬线标题 + 克制的配色 + 圆角 + 层次阴影传达"两个人的私密空间"
- **像素风**：圆角矩形、像素河豚 logo、`pixel-btn`/`pixel-input` 等控件，但克制不喧宾夺主
- **柔和动效**：背景像素漂浮物（爱心/星星/小河豚）+ 鼠标视差，光斑气泡缓慢上浮

## 视觉语言（实现层）
- **主色**：珊瑚橙 `#E56B3A`（`--primary`）/ 暖米 `#F6F1EA`（`--bg`）/ 深棕字 `#3B3228`
- **辅色**：粉色 `#E87F9F`（纪念日/蜜语）、薄荷绿 `#7FB98A`、暖金 `#F2B45C`、天空蓝（喝水）
- **字体**：Noto Serif SC（标题 `var(--font-head)`）、Noto Sans SC（正文）、Inter（数字）
- **圆角**：卡片 `16-20px`、按钮 `12-14px`、输入框 `10px`
- **阴影**：温暖低对比 `var(--shadow-sm)`，层次清晰但不锐利
- **动效**：背景元素（mote）缓慢漂移 + 鼠标视差；河豚戳一下鼓起（`.puff` 600ms）；气泡淡入

## 给 Codex 的评审请求（可直接发给 Codex）

请把以下指令复制给你的 Codex，Codex 会自动读取本文件并查看 `tools/design-shots/` 里的图片（用 `read` 工具打开图片）：

---

请扮演一位资深产品设计评审。基于 `tools/design-shots/DESIGN_REVIEW.md` 的项目说明和 `tools/design-shots/*.png` 五张截图，从以下角度给出**具体、可执行**的设计意见（每条意见要指出问题位置 + 改进方向）：

1. **整体一致性**：跨页面（仪表板/心愿墙/留言板/移动端）的视觉语言是否统一？有没有"出戏"的地方？
2. **信息层级**：首屏（dashboard）的信息层级是否清晰？用户进来第一眼该看到什么、其次是什么？是否有视觉重点争夺？
3. **配色与对比度**：珊瑚橙 + 暖米的主色在不同模块的运用是否协调？文字与背景的对比度是否够（特别是 `muted` 文字）？有没有哪个颜色用得突兀或不够？
4. **排版与节奏**：标题/正文/数据的字号阶梯、字重、行高是否合理？卡片间距、padding 节奏有没有"过紧"或"过松"的地方？
5. **像素风的运用**：哪些地方像素感（圆角+马赛克边框）恰到好处？哪些地方为了像素而像素，破坏了精致感？河豚 logo 和图标系统是否协调？
6. **双人/温度感的表达**：这是"两个人的工作台"，目前哪些设计元素传达了亲密感/温度？哪些地方看起来更像通用 productivity 工具、缺少人情味？
7. **移动端**：390 宽下的导航、卡片堆叠、交互密度是否合理？哪些地方移动端体验可以更好？
8. **可改进的具体点**：请指出 5-8 个**可立即动手**的改进（不需要重构级别的），按"影响 × 改动成本"排序。

输出格式：
- 每个角度先一句话总评
- 然后列具体问题（带截图位置描述，如"dashboard 统计卡的颜色对比"）
- 给出"做/不做"建议，避免空泛
- 最后给 3 个"如果只能改一个，我会改"的高优先级建议

不要客气，直说问题。我想要的是能直接照着改的反馈，不是安慰。

## 你怎么发给 Codex（最简步骤）

打开 Codex CLI（终端 `codex`），执行以下两件事之一：

### 方式 A：让 Codex 读文件（推荐，最稳）
直接对 Codex 说：

```
请读 `tools/design-shots/DESIGN_REVIEW.md` 并查看 `tools/design-shots/*.png` 五张截图，
按文档里"给 Codex 的评审请求"那段的要求，从设计角度给具体意见。
```

Codex 会自动用 `read` 工具打开文档和图片，输出评审。

### 方式 B：把图片直接拖进 Codex
在 Codex 交互界面里，把 `tools/design-shots/` 里的 5 张图片拖进对话（终端需支持图片粘贴：iTerm2/WezTerm/Ghostty/新版 Windows Terminal 都支持），然后附上文档里的「评审请求」那段文字。

---

如果 Codex 给出有用的反馈，告诉我哪些方向你想落地，我再帮你改 + 部署。
